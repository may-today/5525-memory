# 数据电台工具空参数兼容日志

- 已确认 `rank_cities` 等工具的 `.optional()` 字段不接受模型传来的 `null`；日期字段还会出现字符串 `"null"`。
- 计划在共享工具 schema 边界将这两种空值规范为 `undefined`，其余无效输入维持 Zod 校验失败。
- 已在共享 schema 中落实该规范化，并在系统提示中要求模型省略未使用字段。
- 同时接回已有的工具调试环境开关，避免类型检查因未使用的配置函数失败。
- 验证：类型检查、Biome lint、diff 空白检查均通过；`rank_cities` 成功清洗 `null` / `"null"`，错误日期仍被拒绝。
- 新发现：模型将 `song_timeline.limit` 序列化为字符串 `"12"`，需在数值可选字段同样兼容纯数字文本。
- 已把 `month` 与各工具的 `limit` 限制为纯整数文本可转换；完整 `song_timeline` 示例现可解析为 `{ concertScope: "selected", limit: 12, section: "all", songTitle: "温柔" }`。
- 追加实测发现模型会把所有未使用筛选条件序列化为空字符串，导致 schema 在 transform 前就因日期、枚举或数值规则失败。已改为 `z.preprocess` 先将空白字符串、`null` 与 `"null"` 归一为省略字段；城市/歌曲/嘉宾排行上限同步从 8 扩到 10，以兼容模型传入的 `limit: "10"`。给出的 `rank_cities` 载荷现解析为 `{ concertScope: "selected", limit: 10 }`，错误日期和 `limit: "11"` 仍会失败。
- 按产品决定，单曲时间线无需人为截断：移除 `song_timeline.limit` 的最大值，只保留正整数校验和未传入时的默认值 12；模型传入 `"100"` 将得到完整请求范围内的最多 100 条记录。
- 全面检查后发现城市/歌曲/嘉宾排行仍在工具 schema 限为 10，报告卡 schema 也分别限排行 8 项、时间线 12 项，导致完整统计会在不同层被截断。现已移除所有统计工具 `limit` 的最大值与报告卡两种列表的最大项数；默认条数和正整数校验保留，月份仍维持 1–12 的业务校验。
- 进一步确认模型会主动填充 `limit`，因此不应只放宽其约束。已从排行和单曲时间线工具 schema 中移除 `limit`，同时删除 D1 查询的 `LIMIT` 与嘉宾排行的数组截断；工具现在只按用户明确的范围/时间/分段筛选并返回完整结果。
